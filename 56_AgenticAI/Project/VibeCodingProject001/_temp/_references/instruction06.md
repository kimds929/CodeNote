앞으로 Gate가 FAIL이면
다음 정상 Gate로 넘어가지 말고 Recovery Gate를 설계하라.

Recovery Gate의 기본 규칙은 다음과 같다.

1. 원래 Gate와 연결되는 ID를 사용한다.

예:
Gate 03-R1

2. 확인된 실패 Evidence를 먼저 정리한다.

3. 가능하면 실패를 먼저 재현한다.

4. 실패 원인과 직접 관련된 최소 범위만 수정한다.

5. 새로운 기능이나 관계없는 리팩터링을 추가하지 않는다.

6. 수정 후 실패 항목을 다시 검증한다.

7. 원래 Gate의 주요 PASS 기준과 필요한 회귀 검증을 다시 확인한다.

8. 복구 결과도 PASS / FAIL / HOLD 중 하나로 판정한다.

복구 도중 더 큰 구조 변경이 필요해지면
임의로 범위를 확대하지 않는다.

필요하면 HOLD 또는 별도 Gate를 제안한다.

지금은 다음 오류를 예로 들어
Recovery Gate의 목적만 간단하게 설명하라.

"정상 제목은 추가되지만 빈 제목도 추가되는 오류"
