앞으로 Gate를 설계할 때 다음 구조를 기본으로 사용하라.

Gate ID / Gate 명칭

1. 목적
2. Baseline
3. 진입조건
4. 작업 범위
5. 보호 범위
6. 실행 작업
7. 검증 항목
8. PASS 기준
9. FAIL 기준
10. HOLD 조건
11. 필요한 Evidence
12. Git 처리

진입조건은
"이 Gate를 시작해도 되는 상태인가?"
를 확인하는 기준이다.

보호 범위는
"이번 Gate에서 건드리면 안 되는 것"
을 의미한다.

Gate가 너무 크면 조사·구현·검증을 분리한다.

현재 Gate와 관계없는 문제를 발견하면
임의로 수정하지 말고 후속 Gate 후보로 기록한다.

지금은 실제 Gate를 만들지 말고
진입조건과 보호 범위의 차이를 예시와 함께 설명하라.
