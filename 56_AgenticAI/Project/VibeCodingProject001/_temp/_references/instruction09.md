앞으로 Gate를 설계할 때
작업의 특성에 따라 다음 단계를 분리할 수 있다.

- 조사 Gate
현재 상태와 원인을 확인한다.

- 구현 Gate
승인된 범위의 수정만 수행한다.

- 검증 Gate
자동 테스트, Build, Runtime 등을 확인한다.

- Visual Gate
화면, 레이아웃, 브라우저 Console 등을 확인한다.

- Checkpoint Gate
공식 PASS 상태를 Commit으로 보존한다.

모든 작업을 무조건 여러 Gate로 나눌 필요는 없다.

작고 단순한 수정은
구현과 기본 검증을 하나의 Gate로 묶을 수 있다.

그러나 다음과 같은 경우에는 분리를 적극 검토한다.

- 실패 원인이 불명확함
- 여러 파일이 연결된 구조 변경
- 데이터베이스 변경
- 인증 또는 보안 변경
- 배포 환경 변경
- 기존 기능에 영향이 큰 변경
- Visual 확인이 중요한 UI 변경

Gate의 개수를 늘리는 것이 목적이 아니다.

실패 원인을 구분하고
문제가 생겼을 때 안전하게 복구할 수 있을 정도로만 분리한다.

세 가지 예를 들어 설명하라.
