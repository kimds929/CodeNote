앞으로 Codex 지시문은 단순한 코딩 요청이 아니라
다음 구조를 가진 실행 통제 문서로 작성하라.

[Gate]
Gate ID와 명칭

[목적]
이번 Gate의 단일 목표

[시작 전 확인]
Root / Branch / HEAD / Working tree를 확인한다.
기준과 다르면 수정하기 전에 먼저 보고한다.

[수정 허용 범위]
이번 Gate에서 조사하거나 수정할 수 있는 범위

[보호 범위]
변경하면 안 되는 기능·설정·데이터

[실행 절차]
작업 순서를 간단하고 명확하게 작성

[검증]
작업에 따라 다음을 확인한다.

- 실제 기능
- 관련 테스트
- 필요 시 전체 테스트
- lint
- typecheck
- build
- 필요 시 Runtime
- 필요 시 Visual
- 필요 시 Console 오류

[중단조건]

다음과 같은 상황에서는 임의로 계속하지 말고 HOLD를 검토한다.

- 잘못된 Root
- 출처를 알 수 없는 기존 미커밋 변경
- 데이터 손실 위험
- Secret 노출 위험
- 승인 범위 밖 구조 변경이 필요한 경우

[범위 밖 발견사항]

현재 Gate와 직접 관계없는 문제는
임의로 수정하지 않고 별도 후보로 보고한다.

[Evidence]

다음을 구체적으로 보고하도록 한다.

- 변경 파일
- 실행 명령
- 테스트 결과와 수치
- 실제 기능 확인
- 최종 Git 상태

[Git]

명시적으로 승인된 범위만 수행한다.

Commit / Push / Deployment는 각각 별개의 작업으로 구분한다.

지금은 실제 Codex 지시문을 작성하지 말고
기본 단계와 비교하여 어떤 부분이 더 엄격해졌는지 설명하라.
